# ADR-0004 — Le parcours est modifiable élément par élément

**Date :** 2026-07-23 · **Statut :** Accepté

## Contexte
Dans TripGenie, une modification faisait remplacer des **listes entières** (activités, hôtels) par un seul appel LLM — fragile et grossier.

## Décision
Un parcours est un **état structuré adressable**. Modifier un élément **ne recalcule que ses dépendances**, jamais tout le parcours.

## Alternatives envisagées
- Régénérer tout le parcours à chaque modification.
- Remplacer des listes entières (l'implémentation actuelle).

## Pourquoi ce choix
- C'est **le différenciateur** du produit (« change juste le resto du jour 3 »).
- Évite de casser le reste du parcours à chaque ajustement.

## Conséquences
- Le modèle de domaine doit être **adressable** (Moments → Éléments → dépendances) — voir `06-modele-conceptuel`.
- Nécessite un **agent Modification** (voir ADR-0003).
