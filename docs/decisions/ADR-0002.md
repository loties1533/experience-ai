# ADR-0002 — Conserver Express (pas de migration vers Next.js)

**Date :** 2026-07-23 · **Statut :** Accepté

## Contexte
Question ouverte : réécrire le back en Next.js pour unifier front + back ?

## Décision
**Garder Express** comme back-end et moteur d'orchestration IA.

## Alternatives envisagées
- Réécrire le back en routes API Next.js.
- Hybride : Next.js pour le front, Express conservé pour l'IA.

## Pourquoi ce choix
- La génération IA est **longue** (10-30 s, appels en cascade) → mal adaptée au serverless (timeouts) que pousse Next.js.
- Le back Express est **déjà solide** (services, Prisma, ~303 tests).
- L'atout SEO/SSR de Next est **faible en B2B** (vente par prospection, pas par Google).

## Conséquences
- Pas de réécriture du back.
- Next.js reste envisageable **plus tard, pour un front vitrine uniquement**, sans toucher au moteur.
