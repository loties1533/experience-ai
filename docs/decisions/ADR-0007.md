# ADR-0007 — Le parcours se persiste comme un agrégat (une table, contenu JSON validé)

**Date : 2026-07-23 · Statut : Accepté**

## Contexte
Le sprint R2 traduit le modèle de domaine ([06-modele-conceptuel](../06-modele-conceptuel.md)) en persistance. L'agrégat Parcours est profond (timeline → moments → éléments → alternatives / contraintes / réservation) et il se charge et se sauvegarde **toujours en entier** : la modification ciblée (invariant 3) est de la logique de domaine, en mémoire, pas du SQL.

## Décision
Une seule table `parcours` :
- des **colonnes de projection** pour ce qu'on requête ou liste (propriétaire, texte d'intention, visibilité, dates) ;
- une colonne **`contenu` (JSONB)** qui porte l'agrégat complet, sérialisé tel quel depuis le domaine.

Le **dépôt** (`server/depots/depotParcours.ts`) est la seule frontière : il valide `contenu` avec `ParcoursSchema` **à chaque lecture** (une ligne corrompue ne franchit jamais la frontière) et dérive les colonnes de projection **à chaque écriture** (elles ne divergent jamais du contenu).

## Alternatives envisagées
1. **Normalisation complète** (tables moments, elements, alternatives, contraintes…) — 7-8 tables, des migrations à chaque évolution du domaine, des jointures pour reconstruire ce qu'on recharge de toute façon en entier.
2. **Tout en JSON, zéro colonne** — impossible de lister « mes parcours » sans désérialiser chaque ligne.

## Pourquoi
- Le domaine reste la source de vérité de la **forme** ; la base ne connaît que l'enveloppe. Une évolution du modèle = une évolution de schéma Zod (+ migration de données si besoin), pas une cascade de tables.
- Cohérent avec la Constitution : « Zod à toutes les entrées » — la base est une entrée comme une autre.
- Le pattern a déjà fait ses preuves ici (`pack_data Json` de TripGenie), on en corrige le défaut (aucune validation en lecture) au lieu de le reproduire.

## Conséquences
- Pas de requête SQL *dans* la timeline (ex. « tous les parcours contenant un resto ») — acceptable au MVP ; si le besoin naît, on ajoutera une projection dédiée, pas une normalisation.
- Le dépôt doit rester la **seule** porte d'accès à la table (aucun `prisma.parcours` hors de lui).
- La table `parcours` coexiste avec les tables Pack jusqu'à la bascule (sprint R6), qui supprimera les anciennes.
