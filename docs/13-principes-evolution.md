# 13 — Principes d'évolution

**Pas la roadmap. Les règles qui filtrent chaque nouvelle fonctionnalité.**

> Distinct de la **Constitution** (→ `01-philosophie`, les *lois* du produit).
> Ici, c'est la **checklist opérationnelle d'acceptation** d'une feature.

Une nouvelle fonctionnalité entre **seulement si elle coche TOUT** :

- ✓ elle **améliore un parcours** (pas juste une option de plus) ;
- ✓ elle reste **générique** (marche pour un voyage, une soirée, un festival, un séminaire) ;
- ✓ elle préserve la **modifiabilité** (élément par élément) ;
- ✓ elle respecte la **philosophie** et la **Constitution** ;
- ✓ elle est **compatible avec tous les contextes** (solo / couple / groupe / famille) ;
- ✓ elle ne crée **pas de dette produit**.
- ✓ elle ne dégrade pas la **vérité des données** : source, confiance et
  incertitude restent explicites ([doc 14](14-fiabilite-parcours.md)).

**Un seul « non » → la fonctionnalité ne rentre pas.**

> C'est ce document qui évitera, dans deux ans, d'ajouter une fonctionnalité qui casse la vision.
